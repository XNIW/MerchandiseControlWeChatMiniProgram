# WMP-017 — Controlled mutation contract and permission model

- Status: `REVIEW`
- Classification: `FOUNDATION_IMPLEMENTED; CONTROLLED_LANE_BYPASS_REMEDIATION_REQUIRED`
- Parent/epic: `WECHAT-003`

- Opened / updated: 2026-08-12 / 2026-08-13

## Context and objective

Define and verify the single server-authoritative contract through which the Mini Program may perform controlled catalog mutations. Reuse the Admin Web service layer behind a thin bearer-authenticated Mini adapter. The client may display capability state but may not derive permissions, write Supabase tables directly, create audit records or construct trusted sync events.

## Dependencies and files to read

- `WECHAT-003.md`, Admin catalog-mutation ADR-003, actual catalog schema/RLS and Admin mutation services.
- `docs/architecture/API_CONTRACT.md`, `docs/security/THREAT_MODEL.md`, `docs/PARITY_MATRIX.md`.
- Android/iOS permission, revision, tombstone, catalog-text and sync-event contracts.
- Admin permission helpers and the server-provided `can_write`/catalog capability; never infer capability from a client role label.

## In scope

- Typed mutation envelope, body limit, timeout, correlation ID, rate limit and idempotency key.
- Server validation of session, active profile/shop/membership, real permission, target shop/entity state and current revision.
- Sanitized responses and stable errors including unauthenticated, membership/permission/suspension, not-found, duplicate, invalid relation/price/image, conflict/stale and retryable failures.
- Audit and standard outbox/sync emission by the canonical server transaction or a documented fail-closed/compensating boundary.
- Permission matrix for viewer, authorized owner/manager and platform admin without an implicit shop grant.

## Out of scope

- Mini UI forms, image processing, Excel import, sales/staff writes, direct PostgREST DML or a second CRUD implementation.
- Client-supplied roles, actors, audit payloads, sync metadata or service credentials.

## Files potentially involved

- Mini typed contracts, HTTP client, capability state and contract tests.
- Admin ADR-003, Mini adapter routes, canonical services, permission helpers, migration/RLS and pgTAP/foundation tests.
- Shared catalog-text, product-image and sync-recovery fixtures.

## Acceptance criteria

- [ ] ADR-003 names one canonical service layer and documents permission, concurrency, idempotency, audit, sync, image cleanup, archive/restore and rollback behavior.
- [ ] Every mutation independently validates bearer/session, profile, shop, membership, permission, target `shop_id`, entity state and expected revision server-side.
- [ ] Viewer and platform admin without active shop membership receive sanitized denial with zero data/audit/sync mutation.
- [ ] Authorized owner/manager capability is returned by the server and never reconstructed from role strings in the Mini Program.
- [ ] An idempotency replay with the same key/body returns one logical result; key reuse with a different body is rejected.
- [ ] A stale expected revision returns a conflict with zero partial mutation; a fresh retry produces exactly one audit and sync outcome.
- [ ] Request bodies, timeouts, rate limits, error details and correlation identifiers are bounded and privacy-safe.
- [ ] Catalog values use the shared `catalog_text_policy_v1` fixture; barcode identity is not normalized differently by the Mini.
- [ ] No Mini bundle contains AppSecret, service role, direct mutation credentials or trusted audit/sync constructors.

## Risks and remaining problems

- The controlled adapter derives the actor server-side and its service-role-only RPC rechecks membership, permission, shop, state, revision and idempotency. However, an ordinary WeChat Supabase bearer can still reach legacy/table same-shop catalog sinks directly, bypassing this lane and its OFF feature flag. Coordinated RLS/grant/token scoping is required before activation.
- Live rate/WAF behavior, authorized runtime conflicts and visual workflow remain external evidence gaps.

## Execution notes and worklog links

The complete Mini, Admin and scoped database gates pass. This evidence validates the controlled lane, not the removal of alternate same-shop write sinks. See `docs/AI_WORKLOG.md`.
