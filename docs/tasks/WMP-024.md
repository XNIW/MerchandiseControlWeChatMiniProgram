## Context and objective

Extend WMP-012 so sales and catalog caches converge after external events and local mutations. Evaluate, in order, a compatible private Supabase Broadcast channel, official Mini Program WebSocket support, an existing secure server gateway and finally bounded polling. No safe private WebSocket path or measured live latency is currently proven, so the actual classification is `REVIEW_WITH_LIMITATION` and the UI must continue to say automatic update—not realtime.

## Risks and remaining problems

- A topic keyed only by caller-supplied `shop_id` can leak cross-shop activity even with payload-free events.
- Old in-flight requests can repopulate a cache after account/shop switch unless scope generations are checked at commit.
- Polling increases latency and network/battery use; it remains a product limitation, not silent completion.
- Background timers and reconnect behavior require real DevTools/runtime verification.
