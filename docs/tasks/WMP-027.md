## Context and objective

Consume canonical `sync_events` incrementally with the same fail-closed semantic
policy as Android/iOS, without polling full catalog/sales pages.

## Dependencies and files to read

- Admin WECHAT-004 delta/checkpoint RPCs, Android/iOS apply policy, Mini caches
  and DEC-001 adaptive polling.

## In scope

- Per-user/shop watermark, epoch, cache generation, 3–30 second adaptive
  polling, entity-targeted reload, burst dedupe, gap/retention reconcile and
  controlled epoch bootstrap.

## Out of scope

- A fourth sync engine, full-payload invalidations, public topics or a realtime
  product claim.

## Files potentially involved

- Mini sync coordinator/state, BFF read client, app lifecycle, caches and tests.

## Acceptance criteria

- [x] Active delta target begins near 3 seconds and backs off to 30 seconds idle.
- [x] Events reload only affected entities and advance a scoped watermark.
- [x] Gap/lost watermark reconciles; epoch change invalidates and bootstraps.
- [x] Logout/shop/account/revocation fences in-flight publication and purges scope.
- [x] Sales/refund read-only invalidations cannot create sale/refund/void writes.
