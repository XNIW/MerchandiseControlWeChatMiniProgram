## Context and objective

Make every controlled Mini catalog mutation auditable and convergent through the existing ecosystem rather than a WeChat-only channel. Expose a safe, paginated catalog mutation history projection distinct from Android/iOS inventory-counting history and from raw technical audit logs.

## Dependencies and files to read

- WMP-017…WMP-020 and the WMP-021 decision outcome.
- Admin audit services, history projection, sync-event/outbox contract and `record_sync_event_v6` boundary.
- Shared sync recovery fixture `task139-sync-recovery-v6.json` and Android/iOS targeted apply, dirty/conflict, tombstone and watermark behavior.
- Existing Mini History page, pagination, session/shop/cache boundaries and localization.

## In scope

- Catalog events for product/category/supplier create/update/archive/restore, price, relation and image changes; import events only if import is later approved.
- Authorized actor/surface/shop/entity/operation/result/summary fields with redacted correlation and business-safe identifiers.
- Filters by date, type, operation and entity, keyset pagination and loading/empty/error/offline states.
- Complete standard sync events, outbox retry/idempotency, archive/restore tombstones and cross-platform fixtures.
- Explicit stale/conflict state; no fabricated client-side auto-merge.

## Out of scope

- Raw tokens/codes/secrets/PIN/passwords, full request payloads, arbitrary PII, cross-shop events or direct `sync_events` table access.
- Treating sync events as an immutable user audit log or reusing Android “History” as catalog mutation audit.
- A separate WeChat sync channel.

## Files potentially involved

- Mini History page/client/contracts/filters/locales/cache tests.
- Admin audit mutation/projection, Mini history adapter, outbox/sync writer, migration/RLS and pgTAP/foundation tests.
- Android/iOS fixture receivers and shared recovery fixture tests.

## Acceptance criteria

- [ ] Every successful catalog/price/image mutation emits exactly one authorized audit outcome and the required standard sync event(s); failure before commit emits no false success.
- [ ] History exposes only date/time, personal actor, supported surface, shop, entity type, safe identifier, operation, summarized changes, result and redacted correlation.
- [ ] Product/category/supplier/image/price event taxonomy covers every WECHAT-003 operation; Excel events remain absent while WMP-021 is deferred.
- [ ] History reads revalidate active session/profile/shop/membership/permission, are keyset-paginated and deny shop A/B crossover.
- [ ] Sync event `changed_count` equals complete unique remote IDs and respects canonical chunk limits; metadata contains no barcode/name/price/token payload.
- [ ] Repeated client request and repeated event delivery do not duplicate entity, price history, audit or visible history rows.
- [ ] Clean Android/iOS caches apply create/update/tombstone/restore; dirty local state blocks destructive apply/watermark and surfaces review/conflict.
- [ ] Mini refetch after mobile/Admin mutation updates list/detail/history/cache without requiring a full catalog download.
- [ ] Fixture tests cover Mini→Admin/Android/iOS, mobile→Mini, price/image/relation/archive/restore, duplicate event, conflict and shop isolation.
- [ ] Live convergence is not claimed unless an authorized environment/device run is captured.

## Risks and remaining problems

- Audit written after business commit can be missing; audit written before rollback can falsely report success.
- Incomplete entity-ID chunks or client-authored payloads can strand mobile watermarks or permit sync-event forgery.
- History projection can leak cross-shop names, actors or change details if it reads raw audit data indiscriminately.
- Android/iOS conflict-policy helper fixtures do not prove full production field-level merge UI; the Mini must expose real server conflicts.
- Passing automated route/database/fixture evidence does not prove live outbox delivery, device conflict UX or authorized cross-surface latency.
