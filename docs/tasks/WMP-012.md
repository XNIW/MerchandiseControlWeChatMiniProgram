# WMP-012 — Live sales invalidation and refresh

- Parent: `WECHAT-002`
- Status: `REVIEW / CHANGES_REQUIRED`

Implementation evidence: the temporary fallback now polls adaptively from 3 to 30 seconds, stops in background, resumes in foreground and applies backoff. No compatible private shop-scoped invalidation channel or live latency measurement was proved, so this task is explicitly incomplete.

## Scope

Evaluate official Mini Program WebSocket and Supabase Realtime compatibility. Prefer a private, shop-scoped, payload-free invalidation path. Until proven, provide bounded adaptive foreground polling, deduplication, backoff and visible automatic-update wording.

## Acceptance criteria

- Background refresh stops immediately and foreground refresh resumes safely.
- Duplicate/burst invalidations cannot create duplicate rows.
- Revoked membership fails closed on the next API request.
- Polling is never labelled realtime; measured latency and the limitation are documented.

## Required tests

New sale/refund fixtures, burst/deduplication, reconnect/backoff, shop A/B, membership revocation, no-sensitive-payload and measured latency.
