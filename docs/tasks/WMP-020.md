## Context and objective

Allow authorized users to change current product prices and manage the versioned private product image through the canonical cross-platform contracts. Price changes must update the current field and append canonical price history. Image bytes travel only through bounded authorized upload URLs; the client stores only version metadata and bounded image cache entries.

## In scope

- Purchase/retail current-price mutation where the real permission/model supports it, with append-only history.

## Acceptance criteria

- [ ] A price request accepts only a finite canonical numeric value within the real domain; locale formatting is presentation-only.
- [ ] A successful price change atomically updates the current value, appends one history row and emits one audit/sync outcome; replay cannot duplicate history.
- [ ] Unchanged/exactly deduplicated prices follow the canonical service policy and never fabricate history.
- [ ] Image processing follows the shared v1 contract: JPEG main/thumb variants, bounded dimensions/bytes, orientation/sRGB and metadata/integrity checks.
- [ ] Intent returns only `noop` or an authorized upload requirement; finalize activates a verified version and replacement follows canonical cleanup.
- [ ] Remove requires the current expected version and is idempotent; a stale version returns an explicit conflict without clearing the local image.
- [ ] Bucket remains private, signed URLs are short-lived/memory-only, read batches are at most 16 and shop A cannot resolve shop B content.
- [ ] Client never chooses a Storage path or persists upload/signed URLs; cache keys include account/shop/product/version/variant and purge on account/shop/replace/remove.
- [ ] Viewer, cross-shop, invalid/oversized/malicious image, orphan, replay, transient retry and permanent-failure tests pass.
- [ ] Authorized DevTools evidence covers choose/compress/upload/finalize/replace/remove without exposing sensitive URLs or identifiers.

## Risks and remaining problems

- Image decompression, malformed JPEGs and oversized dimensions can exhaust Mini memory before upload.
- Upload success without finalize can orphan objects; finalize and cleanup need an authoritative bounded lifecycle.
- Signed URL leakage or cache reuse across accounts/shops is a cross-shop disclosure risk.
- Price precision drift or a separate history write can desynchronize current price, audit and mobile convergence.
- Durable server image-intent replay/idempotency and bounded admission now have focused database evidence; orphan cleanup and byte processing still require live authorized runtime proof.
