# WMP-018 — Product create, edit, archive and restore

- Status: `REVIEW`
- Classification: `MINI_IMPLEMENTED; SERVER_AND_LIVE_VALIDATION_REQUIRED`
- Parent/epic: `WECHAT-003`
- Owner: Mini Program owns native form UX; Admin Web owns every mutation, authorization, audit and sync side effect

## Context and objective

Add a safe Mini Program workflow for authorized personal users to create and edit real product fields and archive/restore products through WMP-017. Preserve read-only behavior for viewers, reject stale edits explicitly, and make server state—not optimistic local state—the source of truth after every mutation.

## Dependencies and files to read

- WMP-017 and the Admin product mutation/archive contract.
- Shared `catalog_text_policy_v1` fixture and Android/iOS product/revision/tombstone behavior.
- Existing Mini catalog list/detail, locale, session, bounded cache and stale-request suppression code.
- Real Admin schema for barcode, item number, names, category/supplier, prices, image reference, update revision and archive marker.

## In scope

- “New product”, edit and archive/restore actions gated by server capability.
- Real product fields only; local basic validation and definitive server validation.
- Saving, double-submit prevention, error/offline/retry, unsaved-form protection and archive confirmation.
- Duplicate barcode, invalid relation, stale-version conflict, session/membership/shop suspension and permission-denied states.
- Refresh detail and invalidate affected list/entity/history caches only after authoritative success.

## Out of scope

- Hard delete, camera barcode scanning, inventory/sales writes, invented stock/cost/margin fields, client-side permission decisions or direct Supabase DML.
- Excel import and image byte processing, which are governed by WMP-021 and WMP-020.

## Files potentially involved

- `miniprogram/pages/database/`, `miniprogram/pages/product-detail/`, new bounded form pages/components, typed clients/contracts and locale dictionaries.
- Focused Mini mutation/cache/session tests and Admin route/service/pgTAP tests.
- Shared catalog text fixture consumed without modification.

## Acceptance criteria

- [ ] Authorized UI exposes create/edit/archive/restore; viewers see an explicit read-only state and no actionable mutation control.
- [ ] Form fields match the real schema and preserve existing values; no missing value is silently overwritten.
- [ ] Barcode follows the exact cross-platform strict policy, remains required and unique server-side, and is never case-folded or transformed differently.
- [ ] At least one real product-name/item-number fallback is enforced consistently with the canonical service.
- [ ] Price is sent as a finite canonical JSON number, never a localized formatted string.
- [ ] Saving prevents duplicate submit, retains recoverable form input on error/offline and refreshes authoritative detail on success.
- [ ] Update/archive/restore carries the actual expected revision/version; stale state returns an explicit conflict and causes no partial write.
- [ ] Archive uses the canonical soft-delete/tombstone model and restore reactivates the same remote identity; no hard delete is introduced.
- [ ] Successful mutations invalidate list/detail/history/image caches narrowly and do not duplicate rows after replay.
- [ ] Unit/API/pgTAP tests cover create, edit, duplicate barcode, invalid relation, viewer, cross-shop, stale version, archive/restore, replay and session expiry.

## Risks and remaining problems

- Schema assumptions can corrupt optional fields; every editable field must be confirmed against generated types and migrations.
- Live concurrent-edit behavior still requires an authorized runtime check even though the server CAS path passes automated database evidence.
- Local Android hard deletion is cache behavior and must not be copied into the Mini/server contract.
- Ambiguous attempts survive only for the current page instance; durable server replay safety remains mandatory.
- DevTools usability, long localized text and device offline recovery remain unproven.
